## مسؤولية الملفات

| المسار | المسؤولية الحالية أو المخطط لها |
|---|---|
| `src/checker.py` | نقطة التشغيل والمنطق الحالي للتطبيق؛ ما زال يحتوي على وظائف متعددة وسيُقسّم تدريجيًا |
| `src/config.py` | نماذج الإعدادات والتحميل والحفظ والتحقق من القيم |
| `src/models.py` | نماذج النتائج والحالات وبيانات الاعتماد وإعدادات البروكسي |
| `src/telegram_client.py` | مكان فصل الاتصال مع Telegram في مرحلة لاحقة |
| `src/exporters.py` | مكان فصل تصدير JSON وTXT وCSV وHTML |
| `src/analysis.py` | مكان فصل تحليل النتائج والكلمات الشائعة |
| `src/ui.py` | مكان فصل القوائم وقراءة الإدخال من الطرفية |
| `src/scanners/` | حزمة فاحصات المنصات المختلفة |
| `docs/` | أدلة الاستخدام والإعداد والبنية |
| `tests/` | اختبارات الصياغة والسلوك |

## مبدأ التقسيم

ينبغي أن يكون لكل وحدة سبب واحد للتغيير. فالتعامل مع الشبكة لا ينبغي أن يعتمد على طباعة القوائم، كما لا ينبغي أن تعرف وظيفة التصدير تفاصيل بوت Telegram. عند نقل وظيفة من `checker.py` إلى وحدة مستقلة، أبقِ الواجهة العامة صغيرة وأضف اختبارًا لها قبل حذف النسخة القديمة.

## مسار إعادة الهيكلة المقترح

ابدأ بنقل الثوابت وإعداد التسجيل، ثم انقل طبقة Telegram، وبعدها وظائف التصدير والتحليل. في كل خطوة شغّل الاختبارات، وتحقق من أن نقطة التشغيل القديمة ما زالت تعمل. بعد استقرار الوحدات الجديدة يمكن تقليل `checker.py` إلى تهيئة التطبيق واستدعاء واجهة المستخدم.
